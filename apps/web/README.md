# HYDROOVERITY M04 web application

M04 private-development frontend. See the [execution ledger](../../docs/testing/M04_EXECUTION_LEDGER.md) for actual validation and the [route/API matrix](../../docs/testing/M04_ROUTE_AND_API_MATRIX.md) for delivered and deferred scope. Owner engineering review is required before merge.

Run commands from this repository root unless a command explicitly changes directory. The application uses the 58 implemented M03 operations. FastAPI remains the identity and domain authority. No public deployment is authorized or supported by M03 configuration.

## Install and compile

Validated locally with Node 24.21.0 and pnpm 11.25.0. Exact dependencies and the lockfile belong to `apps/web`; scientific Python packages remain in their existing isolated environments.

```powershell
Set-Location apps/web
pnpm install --frozen-lockfile --ignore-scripts
pnpm run contracts
pnpm run typecheck
pnpm run lint
pnpm run test
pnpm run build
pnpm run start
```

The build explicitly selects Next’s supported Webpack builder after a reproducible local Turbopack PostCSS-worker failure. The production build does not require network fonts.

Next listens on `127.0.0.1:3000`. The public pages can be previewed there. For real authentication, use the optional HTTPS proxy below; Secure cookies must not be weakened to make HTTP login appear functional. The Next API rewrite has one fixed loopback upstream and is not a general proxy.

## Real backend and optional frontend HTTPS

First follow the [M03 backend guide](../../services/api/README.md) to prepare the private PostgreSQL runtime and accounts. Keep private configuration, mail, certificates, screenshots and database files outside the checkout. Start the API on loopback port 8000 using its existing `hydro.local api` command.

The backend-only HTTPS proxy remains unchanged. Stop only that proxy if it occupies port 8443, then opt into the frontend proxy:

```powershell
# From repository root; use your actual isolated Python and private paths.
& $py apps/web/tools/local_proxy.py --certificate "$private/localhost.crt" --key "$private/localhost.key"
```

This routes `/api/v1/*` to the API on 8000 and page GET/HEAD requests to Next on 3000. It binds only `127.0.0.1:8443`, blocks internal paths, limits requests to 16 KiB and suppresses access logging. It is a local development helper, not a production reverse proxy. Trust the specific development certificate explicitly in your test client; do not disable all TLS verification or install an unreviewed machine trust root. The browser test configuration uses the exact generated certificate SPKI allow-list, with `ignoreHTTPSErrors: false`.

## Synthetic browser acceptance

`tools/prepare_browser_fixture.py` creates/resets **only** the exactly confirmed `hydro_disposable_m04` database. It reuses existing safe database roles without changing their passwords and requires a matching dedicated M04 marker before resetting an existing database. It never resets the M03 database. The operator/runtime inputs are the private files prepared by M03; the output directory must be outside this repository.

```powershell
& $py apps/web/tools/prepare_browser_fixture.py --operator-config "$sourcePrivate/operator.json" --runtime-config "$sourcePrivate/runtime.json" --private-directory "$m04Private" --confirm-disposable-database hydro_disposable_m04 --openssl $openssl
# Start API with $m04Private/runtime.json, the optional proxy with its certificate,
# and the production Next server. No operator credentials enter the API process.
$env:HYDRO_M04_BROWSER_FIXTURE = "$m04Private/browser.json"
$env:HYDRO_M04_SCREENSHOTS = "$m04Evidence/screenshots"
Set-Location apps/web
pnpm exec playwright install chromium
pnpm run test:browser
# Optional local fallback only when the pinned browser download is unavailable:
# $env:HYDRO_M04_BROWSER_CHANNEL = "chrome"
# pnpm run test:browser
```

The fixture contains only synthetic local identities, with a random private test password. It is never copied to a public directory, source tree, browser bundle or Actions artifact. Playwright traces/video/automatic failure screenshots are disabled to avoid capturing entered identity secrets. Explicit captures use synthetic records after login, not token/password entry. Screenshots are development test evidence, not field observations.

## Map and security decisions

MapLibre renders only currently authorized junction/pipe pages using a blank local style. No basemap tiles, external fonts, geocoder, analytics or location-permission request is required. WGS84 order is longitude, latitude. The accessible list remains available when WebGL fails. Surveyed length and topology uncertainty are retained; no acoustic coverage or exact leak pin is inferred. Citizens never request the internal network endpoints.

Sessions remain Secure/HttpOnly/SameSite cookies. CSRF values and safe mutation retry keys are memory-only. Auth/global writes have no business idempotency key. Tenant writes retain the same key only for an identical body and version; scope changes abort pending requests and queued writes. No automatic stale-version or identity replay occurs. Private responses use no-store and no service worker. Production CSP excludes unsafe-eval; development adds it only for the Next development runtime. Inline styles are allowed for MapLibre’s control/canvas positioning; external script and connection origins remain blocked.
