# Authentication, security and privacy design

M02 issue #2; controls are specified, not implemented or penetration-tested. No production credentials or grants are created.

## One authentication owner

FastAPI owns users, password hashing, sessions, invitations/recovery and authorization. Next.js renders UI/SSR and forwards requests through one same-origin reverse proxy `/api/v1`; no competing NextAuth/browser-JWT identity system. SSR forwards the current cookie only to the fixed internal API, never logs it and uses no-store for private data. No static generation/shared CDN cache for authenticated pages. Reverse proxy controls trusted forwarding headers, TLS and body limits.

Use 256-bit CSPRNG opaque session token, SHA-256 verifier at rest, cookie `__Host-hydro_session; Secure; HttpOnly; Path=/; SameSite=Lax`, no Domain. Server idle30min/absolute12h, recent-reauth10min for sensitive governance, rotation after login/reset/privilege-sensitive changes; revoke on logout, reset or account suspension. Preauth session10min supports session-bound CSRF bootstrap. GET/auth/csrf returns synchronizer token to same-origin code, stores verifier; every cookie-authenticated mutation including login requires X-CSRF-Token and validated Origin/Referer/Fetch-Metadata policy. SameSite is defense in depth, not the CSRF mechanism. Local Compose design includes local HTTPS reverse proxy; do not silently weaken production cookie settings for localhost. No tokens in localStorage or URL query strings; reset links remove token from browser address promptly and use Referrer-Policy:no-referrer.

Argon2id password hashes with unique salts and benchmarked parameters at least OWASP's19MiB/t2/p1 floor; actual parameters/load tests in M03. Minimum15/max128 characters, allow paste/password managers, no silent truncation. Generic login/recovery messages avoid account enumeration; bounded exponential throttles, not permanent attacker-triggered lockouts. Proposed pilot limits: login/recovery5/min/IP and20/hour normalized account; complaints10/day/member; general API120/min/session; upload quota25MiB/member/day. These are tunable security policy, not measured capacity. Staff invite acceptance binds verified identity and exact tenant role; citizens self-register only for enabled utility with CITIZEN. Future MFA fits the same owner; no second auth provider now.

## Tenant/resource enforcement

Global identity, multiple memberships, scoped primary roles. Backend validates tenant path, active membership, explicit permission, row organization, resource ownership/assigned parent and state/version on every request. Composite FKs prohibit cross-tenant relationships; runtime RLS provides additional protection with safe transaction-local context and non-owner principals. Citizens see own safe report DTOs only; tracking number is not a bearer credential. Technicians receive current assigned briefs and permitted evidence, no full topology/citizen contact. ADMIN governs its tenant only and does not inherit engineer/evaluator privileges. Existing-user invitations cannot change another tenant membership. Last active ADMIN protection avoids lockout. Role changes/audit settings/revocations require recent reauth and reason. No universal super-admin UI.

SSE, reports and downloads repeat authorization, not just page load. Device/simulator bearer credentials are hashed, scoped, expiry/revocation checked and unable to use human APIs. Profile bindings prevent SIMULATION->FIELD relabeling. Restricted truth DB/object credentials are unavailable to ordinary API/detector principal. Audit safe actor/action/resource/request/time, not password/token/body/IP dumps. Logs minimize personal data; request IDs support diagnosis without exposing traces.

## Private upload lifecycle

JPEG/PNG/WebP only, <=5MiB and decoded<=12 megapixels, <=5 complaint photos. Server reserves scoped ticket and ignores supplied filenames/storage keys. Authenticate/authorize before each byte upload, completion, link and download; require explicit consent. Quarantine outside web root/private object namespace, checksum/size/magic/type/decode validation, reject malformed/polyglot/oversized images, reencode safe derivative and strip EXIF/GPS. Never serve original uploads. Malware scan is a future adapter; absent scanner/failed checks leaves QUARANTINED, not CLEAN. Clean derivative receives nosniff/no-store and attachment content disposition where appropriate. No public bucket, permanent signed URL or executable SVG/HTML/PDF upload.

Draft uploads may have null target only for the current creator/declared purpose and expire24h; linking atomically checks same owner/tenant/parent and CLEAN state. Worker attachments need current assigned parent; reassigned or unauthorized pending files cannot be attached. Referenced evidence pins block ordinary erasure and use documented redaction/retention review. Default clean photo deletion90days after case closure; complaint personal content1year; operational evidence2years; safe audit1year; policies are proposed pilot defaults, not legal-compliance claims. Erasure request is an authenticated support process with holds/verification, not a public destructive endpoint.

## Threat response and deployment gates

Review SQL injection, object-ID access, stored XSS, CSRF, upload decompression, token replay, CSV formula injection, simulation truth leakage, stale offline rights and backup exposure. Use parameterized queries, escaping/CSP, allow-listed redirect destinations, scoped limits, private buckets/volumes and least-privilege connections. Secrets configured out of Git through approved environment references. Backups encrypted/access-controlled; test restore and retention purge. No actuation endpoints or municipal control implemented. M03 must prove negative cross-tenant/own/assigned tests and CSRF/session expiry before exposure.
