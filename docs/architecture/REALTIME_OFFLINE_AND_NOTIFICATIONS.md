# Realtime, offline and notifications

Issue #2; future implementation design only.

## SSE first, polling fallback

Choose same-origin authenticated SSE for one-way monitoring/job/incident summaries. WebSockets add connection/auth complexity without current bidirectional need; mutation remains ordinary HTTP. One shared stream per active organization/browser tab, coalesced across panels; no waveform streaming. Transaction commits business state/history and domain_events outbox atomically. EventEnvelope includes opaque cursor, type/resource/time/mode/safe summary; never ground truth, raw contact, credentials or raw waveform.

Authorize subscription and each emitted event by current role/own/assigned ACL; recheck session/membership at least30s and terminate immediately on known revocation. Heartbeat15s; bounded per-connection queue100events or256KiB. Slow consumers receive reset-required and disconnect; they recover authoritative resource state rather than missing events silently. Last-Event-ID cursor binds organization/filters; retain replay7days. Missing/expired cursor -> reset_required and fetch snapshot plus new cursor; use snapshot watermark to close subscribe race. At-least-once delivery is deduplicated by event ID. Reconnect with jittered exponential1–30s; 401 stops until reauth, 403 stops until permission change, 429 respects retry. Poll event-history/resource snapshots every30s as fallback when stream unavailable, with visible degraded freshness. Freshness uses collection and receipt times, never arrival animation as proof of a live physical sensor.

## Deliberately limited offline field vault

Cache static PWA shell only through service worker; never cache authenticated API responses or internal map tiles through generic HTTP cache. After online assignment authorization, user may explicitly download a minimal WorkerBrief with12h lease: task instructions, safe approximate site text, permitted evidence summary, current version/assignment_version. No full graph, resident contacts, secrets or waveform. No offline GIS promise; licensed tile cache is a later separate decision. External navigation requires explicit handoff and exposes only permitted approximate destination.

Offline queue supports draft inspection notes, materials, photos, external service receipts and proposed repair notes. Assignment changes, role edits, incident transitions, final submission/approval, verification outcome and new sensor provisioning require online authorization. Cached lease grants no server write permission. UI badges: Local draft, Queued, Syncing, Synced, Conflict, Failed; show exact server receipt or pending operation ID and draft expiry.

Use encrypted IndexedDB vault (AES-GCM random IV per record), data key wrapped with a user-entered local unlock passphrase using WebCrypto PBKDF2; calibrated work factor and unlock usability tested in M03/M04. No raw vault key/session cookie persisted alongside data. Key unlocked in memory only; close/logout locks or purges as configured. Device OS encryption/screen lock remains necessary; web encryption cannot protect against active XSS or a compromised unlocked device. Storage may be evicted by browser: request persistence where available, detect quota failures, never promise indestructible drafts. User must acknowledge these limits before enabling offline capture.

Lease expiry stops new cached task access and asks reconnect; encrypted unsynced drafts retained at most72h with24h expiry warnings, then purged by policy. Synced content purged after receipt/24h grace, logout and account switch purge local vault. Forgotten unlock passphrase has no recovery key on server; warn before capture. Lost-device session revocation stops server access, cannot remotely erase an offline device;72h local retention limits exposure but is not a guarantee.

Each queued operation gets UUID operation_id/Idempotency-Key and immutable canonical body fingerprint, base_version and assignment_version. Sync only after online authentication and current membership/assignment check. Same ID/same payload returns original receipt; changed payload ->409. Reassigned task/stale version -> conflict with safe explanation; keep encrypted draft for supervisor reconciliation, never last-write-wins. Server may accept append-only notes after version review but final transitions require fresh If-Match and online confirmation. Upload resumes by bounded whole-file retry (<=5MiB), hash checks and idempotent ticket, not a complex resumable protocol. No automatic retry of denied/invalid actions. Retry5xx with jitter/backoff; expose permanent failure and manual discard/retry.

## Durable jobs and notifications

One PostgreSQL background_jobs queue with SKIP LOCKED claim, bounded concurrency1 initially, lease heartbeat, attempt cap3 and explicit queued/running/cancel/terminal states. API response202 precedes actual work. Simulations keep scientific config in simulation_runs linked to job; generator/truth and detector credentials stay isolated in future worker execution. Cancellation is cooperative: queued ->CANCELLED; running ->CANCEL_REQUESTED then CANCELLED, or SUCCEEDED if completion won the transaction race. Partial outputs stay incomplete and cannot publish final metrics. Expired leases retry with same run/config, no duplicate results; terminal failures retain safe error/reproducibility metadata. Worker cannot spawn arbitrary shell commands from scenario parameters.

Notifications derive from committed domain events, unique recipient/event/template/channel. In-app first; email is optional only after approved provider configuration. No SMS/WhatsApp/push purchase now. Store delivery attempts, retry at1min/5min/30min then mark failed after3 attempts; external timeout can still cause duplicate delivery, so do not claim exactly once. Provider idempotency where available; safe message contains no pipeline coordinates/photo/contact details. Recheck recipient membership/ownership before delivery. Mark read only for current recipient. Failed messages remain visible for supervisor/admin action, never an endless silent retry loop.

Reference: [MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events). All numeric retry/cache limits here are initial product/security policies to test, not measured performance or sensor thresholds.
